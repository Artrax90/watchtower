# 🗼 Watchtower — Modern Infrastructure & Uptime Monitoring System

Автономная, современная и легковесная система мониторинга доступности сервисов, серверов, сетевых портов и SSL-сертификатов с оповещениями в **Telegram** (с поддержкой SOCKS5/HTTP прокси) и мессенджер **MAX**.

Разработано для быстрого развертывания в Docker на Ubuntu / Linux или локально.

---

## 🌟 Ключевые возможности

* **Мульти-проверки для каждого ресурса**:
  * **HTTP / HTTPS**: контроль статус-кодов (2xx/3xx), измерение времени отклика (latency), проверка наличия ключевых слов на странице.
  * **SSL / TLS**: автоматический аудит срока действия сертификата, подсчёт оставшихся дней, предупреждения за 30, 14, 7 и 1 день, детектирование просроченных сертификатов.
  * **TCP Port**: проверка доступности произвольных сетевых портов (PostgreSQL, MySQL, Redis, SSH, SMTP и др.).
  * **Ping (ICMP)**: проверка сетевой связности с определением IP-адреса источника ответа.
  * **DNS Lookup**: резолв доменных имён и контроль корректности записей.
  * **Интерактивные бейджи проверок**: возможность ручного перезапуска отдельной проверки прямо из карточки монитора в один клик.

* **Каналы оповещений**:
  * **Telegram Bot API**:
    * Информативные карточки с разметкой, ссылками и деталями сбоев.
    * **Встроенная поддержка прокси**: SOCKS5 (с удаленным резолвом DNS через `socks5h://`) и HTTP/HTTPS прокси с авторизацией (логин/пароль).
    * Кнопки мгновенного тестирования подключения прокси и отправки тестового сообщения бота.
  * **Мессенджер MAX**:
    * Прямая интеграция через MAX Bot API (`platform-api2.max.ru`).
    * Встроенный доверенный корневой сертификат Минцифры РФ в Docker-контейнере.
  * **Защита от ложных срабатываний (Retry Logic)**: настраиваемый порог подтверждённых неудачных проверок подряд перед отправкой алерта.

* **Интерфейс и UX**:
  * Современный адаптивный UI в темных тонах с поддержкой переключения тем.
  * Прямая навигация по вкладкам (`/overview`, `/monitors`, `/incidents`, `/alerts`, `/settings`).
  * **Плавающая live-шкала проверок**: динамическая анимация сдвига столбиков в реальном времени при получении каждого тика.
  * Подробные тултипы и модальные окна при клике на сбойные (жёлтые/красные) тики с точной датой, причиной и длительностью инцидента.
  * Кастомные модальные окна подтверждения (включая безопасное удаление мониторов).
  * Корректная обработка кликов и выделения текста без случайного закрытия модалок.

* **Безопасность и управление доступом (RBAC)**:
  * **Мастер первого запуска (Setup Wizard)**: при первом старте пустой базы данных система встречает мастера регистрации первичного администратора.
  * **Ролевая модель**:
    * 👑 **Администратор (Admin)**: полный доступ к добавлению, редактированию, удалению мониторов, настройкам алертов и управлению пользователями.
    * 👁️ **Наблюдатель (Viewer)**: режим только для чтения (просмотр состояния мониторов, графиков и истории инцидентов без кнопок модификации).
  * Хэширование паролей (`scrypt`) и безопасные токены сессий.

## 🚀 Быстрый запуск в Docker

### 1. Требования
На сервере должен быть установлен Docker и Docker Compose.

```bash
# Установка Docker на Ubuntu (если еще не установлен)
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
```

### 2. Запуск проекта

Клонируйте репозиторий и запустите контейнер:

```bash
git clone https://github.com/Artrax90/watchtower.git
cd watchtower
docker compose up -d --build
```

Контейнер автоматически соберёт бэкенд, применит миграции SQLite, настроит сертификаты Минцифры и поднимет сервис на порту **3000**.

Веб-интерфейс доступен по адресу:
👉 **`http://<IP_СЕРВЕРА>:3000`**

### 3. Первый вход
1. Откройте `http://<IP_СЕРВЕРА>:3000` в браузере.
2. В мастере первоначальной настройки задайте логин и пароль первого администратора.
3. Готово! Переходите во вкладку **«Мониторы»** и добавляйте первые хосты.

## 🔔 Настройка оповещений

### Telegram Bot
1. Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте **Bot Token**.
2. Получите свой **Chat ID** (например, через [@userinfobot](https://t.me/userinfobot) или добавив бота в нужную группу).
3. Перейдите во вкладку **«Оповещения»** в Watchtower.
4. При необходимости работы через прокси включите тумблер **«Использовать прокси»**, выберите тип (`SOCKS5` или `HTTP`), введите хост, порт, логин и пароль.
5. Нажмите **«Проверить прокси»**, а затем **«Тестовое сообщение»**.

### Мессенджер MAX
1. Найдите сервисного бота **`@MasterBot`** в мессенджере MAX и выполните `/newbot`.
2. Введите токен бота и Chat ID во вкладке **«Мессенджер MAX»**.
3. Проверьте отправку кнопкой **«Тестовое сообщение»**.

## 📁 Структура проекта

```text
watchtower/
├── backend/                  # Сервер Fastify + TypeScript
│   ├── src/
│   │   ├── checkers/         # Модули проверок: HTTP, SSL, TCP, Ping, DNS
│   │   ├── notifiers/        # Модули отправки уведомлений: Telegram & MAX
│   │   ├── db/               # SQLite схема, запросы и индексы
│   │   ├── routes/           # REST API эндпоинты:
│   │   │   ├── auth.ts       # Авторизация, сессии, роли, мастер настройки
│   │   │   ├── monitors.ts   # CRUD мониторов, одиночные запуски проверок
│   │   │   ├── stats.ts      # Статистика, тики, latency, инциденты
│   │   │   └── notifications.ts # Настройка и тест каналов / прокси
│   │   ├── scheduler/        # Фоновый движок периодических проверок
│   │   └── server.ts         # Точка входа Fastify
│   ├── tsconfig.json
│   └── package.json
├── frontend/                 # Клиентская часть (SPA без тяжелых фреймворков)
│   ├── index.html            # Каркас интерфейса и модальных окон
│   ├── styles.css            # Стилистика, анимации тиков, темы, адаптив
│   └── app.js                # Клиентская логика, роутинг, live-обновления
├── data/                     # Директория монтирования SQLite (watchtower.db)
│   └── .gitkeep
├── Dockerfile                # Multi-stage сборка Node.js + доверенные сертификаты
├── docker-compose.yml        # Конфигурация контейнера и проброс портов
├── .gitignore
└── README.md
```

## 💾 Резервное копирование

Вся конфигурация, аккаунты, мониторы и история проверок хранятся в единственной базе данных SQLite в папке `./data/`:
* `data/watchtower.db`

Для создания резервной копии достаточно архивировать эту директорию:
```bash
tar -czvf watchtower-backup-$(date +%F).tar.gz data/
```
